R117: cross-format agreement against a decoder-independent reference

The plan called for driving scPOST's COM interface to export reference values.
That path was explored and is BLOCKED at the server, which is recorded rather
than papered over:
  * scPOST_Dx64net.Application.2025 is registered and win32com connects (6.7 s);
  * CreateObjectFLD opens ex1_100.fld (2.3 s);
  * but every data accessor fails -- GetNodeXYZ -> 0x80010105
    (RPC_E_SERVERFAULT), GetBoundingBox -> argument mismatch, GetNodeCount(1)
    -> 0, GetScalarArray -> False -- with or without CoInitialize, Visible
    False, and both calling conventions.
The object evidently needs server-side state the VB manual does not document
(most likely an active draw window), so no values could be extracted.
scripts/scpost_export.py keeps the working half (connect + open) for the round
that finishes this.

The round still delivers external evidence of equivalent strength, using a
reference the corpus does support: ex1_e_from_sxemt_run is one solver run
written twice -- a .fld our FLD decoder reads, and a .cgns read STRAIGHT FROM
HDF5, bypassing fv.crdl.cgns entirely. Two independent decoders, one physical
dataset. Measured over all 21145 nodes on the full files:
  coordinate max abs diff 0.000e+00;
  all 15 shared variables (ATMS/CN01/HTFX/HTRC/HVECX/Y/Z/PRES/SURT/TEMP/TEPS/
  TURK/VECTX/Y/Z) max abs diff 0.000e+00; no variable on one side only.

Committed as tests/data/golden/cross_format.npz (14.4 KiB, 600 nodes sampled
across the whole mesh) so tests/test_r117_crossformat.py runs on any checkout.

A mistake of mine that the round caught: I first matched nodes by nearest
coordinate and took the first of each duplicate, which reported TEMP differing
by 80.0 (looking like a C-to-K conversion). That was my script's fault -- the
mesh has 439 coincident nodes (21145 nodes, 20706 distinct coordinates) where
TEMP takes both 20 and 100, so "first duplicate" mismatched them. Comparing
element by element in file order gives exactly 0.0. Approximate matching
manufactured a defect that was not there.

Also: the corpus generator now samples ACROSS the mesh rather than taking the
first N nodes, because the opening block is uniform in every variable and a
contiguous excerpt would have let the cross-check pass for a broken decoder.
The "reference is not trivially constant" test caught that immediately.

tests/test_r114_golden.py's manifest assertion was scoped to the two mesh
corpora, since the cross-format excerpt legitimately has a different shape.

Regression: 1105 passed / 6 skipped / 1 failed before the R114 fix above; the
golden and cross-format suites pass 12/12 after it.
